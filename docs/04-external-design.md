# 外部設計(P1)

P1(歌なしで1コーラス完成)の範囲で、画面・保存用API・MCPツールの外から見える振る舞いを定める。歌詞と歌声の画面はP2で追加する。末尾の3点を含めて確定済み。

## 画面一覧

起点は曲一覧で、作業の中心は編集画面。別案・パート設定・書き出しは編集画面の上に重ねて開くパネルとする。

| # | 画面 | できること | 開き方 |
| --- | --- | --- | --- |
| S0 | ログイン | パスキーでログインする。初回はパスキーを登録する。MCPを接続する時の本人確認にもこの画面を使う | ログインしていない時 |
| S1 | 曲一覧 | 曲の一覧表示、曲を開く、新規作成へ、MIDI取り込みへ、曲の削除 | アプリ起動時 |
| S2 | 新規作成 | 曲名、雰囲気(4種から1つ)、テンポ(ゆっくり・ふつう・はやい)を選び、叩き台を作る | S1から |
| S3 | 編集 | 再生・停止・ループ、部品の並びの表示、部品の追加・削除・並べ替え、部品を選んでそこだけ再生、元に戻す | S1で曲を開く、S2・S7の完了後 |
| S4 | 別案の聴き比べ | 対象(メロディ・コード進行・伴奏・全部)を選ぶ、今の案と別案3つを聴き比べる、選ぶ、出し直す | S3で部品を選び「別案を出す」 |
| S5 | パート設定 | パートごとの楽器(10種から)、音量、消音 | S3から |
| S6 | 書き出し | 書き出し先の一覧から選んでファイルを保存する。使えないものは理由を表示、注意書きがあれば表示 | S3から |
| S7 | MIDI取り込み | ファイルを選ぶ、8小節ごとの自動区切りを確認、区切り位置の調整、部品の名付け、取り込む | S1から |
| S8 | 設定 | MCPの接続先URLの表示、パスキーの追加、保存方法の切り替え、ログアウト | S1から |

## 画面の共通ルール

- 音楽用語は画面に出さない。出す場合は一言の説明を添える(例:コード進行→「曲の雰囲気を決める和音の流れ」)
- 保存方法は「自動保存」と「保存ボタン」を設定で切り替えられる。初期値は自動保存で、設定は端末ごとに覚える。自動保存では操作のたびに保存する。保存ボタンでは押した時だけ保存し、未保存の変更があることを表示して、保存せずに画面を離れる時は確認する。どちらでも保存中・保存済み・失敗を画面の隅に表示する
- 他(MCPなど)で曲が更新されていて保存が拒否されたら、「他で更新されました」と表示し、最新を読み込むボタンを出す
- 通信できない時は編集できない状態にし、その旨を表示する
- 失敗の表示は「何が起きたか」と「どうすればよいか」の2つを必ず出す
- タッチとマウスの両方で操作できる。押せる場所は指で押せる大きさにする
- 対応環境はiPadのSafariと、PCのChrome・Edgeの最新版

## 破綻防止の振る舞い

- 叩き台と別案は、曲のキーに合う音だけで作る
- 操作(画面・MCP)で入れる音符がキーから外れていたら拒否し、どの音が外れているかを返す
- MIDIから取り込んだ音符は拒否しない。キーから外れた音があれば注意書きとして知らせる

## ログイン

アプリのログイン(パスキー)とCloudflare Accessの両方を持つ。アプリのログインが「誰の曲か」を決め、Accessは画面の外側の門として自分以外を止める。

| 仕組み | 役割 | 守る範囲 | 将来 |
| --- | --- | --- | --- |
| アプリのログイン(パスキー) | 誰の曲かを決める。MCPのOAuthの本人確認も兼ねる | 保存用APIとMCP | 他の人に公開する時もそのまま使う |
| Cloudflare Access | 自分以外を入口で止める | 画面と保存用API。MCPとOAuthの入口には掛けない | 公開する時に外す |

- パスキーの新規登録はAccessの内側からだけ行える。外から勝手にアカウントを作られないようにするため
- パスキーは複数登録できる。iPadとPCの両方を登録し、1台を失っても入れるようにする
- 曲には持ち主を記録し、APIとMCPはログイン中の人の曲だけを返す
- AIはパスキーを使わない。接続時に自分がログインして許可し、以後は発行された許可証でアクセスする

| 呼び方 | 内容 |
| --- | --- |
| POST /api/auth/register/start・finish | パスキーの登録(開始と完了) |
| POST /api/auth/login/start・finish | パスキーでログイン(開始と完了) |
| POST /api/auth/logout | ログアウト |
| GET /api/auth/me | ログイン中かどうかの確認 |

## 保存用API

画面がCloudflare Workersに対して呼ぶ。すべてログイン済みであることが前提。

| 呼び方 | 内容 | 返すもの |
| --- | --- | --- |
| GET /api/songs | 曲の一覧 | id、曲名、更新日時の並び |
| POST /api/songs | 曲を新しく保存 | 保存した曲データ |
| GET /api/songs/:id | 曲1つを取得 | 曲データ |
| PUT /api/songs/:id | 曲を上書き保存。送る曲データのrevisionがサーバーと一致すること | revisionを1増やした曲データ。不一致なら409 |
| DELETE /api/songs/:id | 曲を削除 | なし |

失敗はすべて同じ形で返す。

```json
{ "code": "revision_conflict", "message": "他で更新されています", "hint": "最新を読み込んでからやり直してください" }
```

| code | 状況 | HTTP |
| --- | --- | --- |
| unauthorized | ログインしていない | 401 |
| not_found | 曲がない | 404 |
| revision_conflict | revisionが一致しない | 409 |
| invalid_song | 曲データの形が正しくない、またはキーから外れた音がある | 422 |

## MCPツール

ClaudeなどがOAuthで接続して使う。書き込むツールはすべてrevisionを受け取り、画面と同じ検査を通す。曲の削除は出さない。

| ツール | 内容 |
| --- | --- |
| get_format_guide | 曲データの書き方と制約(キーに合う音、時間の数え方、楽器の名前)を返す。AIが最初に読む |
| list_songs | 曲の一覧 |
| get_song | 曲1つの曲データ |
| create_song | 曲名・雰囲気・テンポから叩き台を作る。またはAIが作った曲データをそのまま登録する |
| generate_alternatives | 部品1つについてルールによる別案を3つ返す。保存はしない |
| replace_section | 部品1つのコード進行やパートを置き換える |
| update_arrangement | 部品の追加・削除・並べ替え、部品の名前の変更 |
| update_song_settings | 曲名、テンポ、キー、パートの楽器と音量 |
| export_midi | 曲をMIDIファイルにして返す |

## P1でやらないこと

- 歌詞と歌声(P2)
- フル尺への拡張と音量バランスの作り込み(P3)
- 音符1つずつの手編集。変更は別案の選び直しで行う
- 4/4以外の拍子、曲中のテンポ変更、転調

## 確定した点

- 音声の書き出しはP1ではWAVのみ。MP3は後で接続口として足す
- MCPからの書き出しはMIDIのみ。音声は画面から書き出す
- 保存は自動保存と保存ボタンを切り替えられる
