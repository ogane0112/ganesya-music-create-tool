# 接続口設計

接続口は3種類に分け、どれも「曲データを直接書き換えず、結果を返すだけ」という同じ作法で作る。曲への変更はすべて「操作」という1つの窓口を通し、画面とMCPが同じ操作を呼ぶ。末尾の2点を含めて確定済み。

## 接続口の3種類

| 種類 | すること | 該当するもの |
| --- | --- | --- |
| 取り込み | 外部のファイルを曲データに変換する | MIDI読み込み |
| 書き出し | 曲データを外部の形式のファイルに変換する | MIDI書き出し、WAV。将来は楽譜、字幕、DAW向け、配信向け、MP3 |
| エンジン | 曲データの一部を外部に渡し、結果を受け取る | VOICEVOX(音符と歌詞を渡して歌声を受け取る) |

MCPは接続口ではなく、画面と並ぶ「もう1つの操作元」として扱う。

## 共通の作法

1. **曲データを直接書き換えない。** 接続口は結果を返すだけで、反映と保存は本体が行う。接続口の不具合で曲が壊れるのを防ぐ。
2. **本体は接続口の中身を知らない。** 接続口は登録簿に登録し、本体は登録されたものを一覧に出すだけ。足す時は1ファイル作って登録する。
3. **使えるかどうかを自分で申告する。** VOICEVOXが起動していない、iPadで開いている、といった時は「使えない」とその理由を返し、画面はボタンを押せない状態にして理由を表示する。
4. **情報が落ちる時は申告する。** 書き出し先の形式で表せないもの(例:MIDIにはコード進行がそのままは入らない)があれば、結果と一緒に注意書きを返す。
5. **失敗は決まった形で返す。** 種類、人が読める説明、対処方法の3つ。画面はどの接続口の失敗も同じ見た目で出せる。
6. **取り込んだ結果は必ず検査を通す。** 曲データとして正しい形かを本体が確かめてから保存する。
7. **接続口だけが使う情報は専用の置き場に入れる。** 曲データのextensionsの中に、接続口の名前で区切って置く(例:VOICEVOXで選んだ声)。

## 接続口の形

取り込み・書き出し・エンジンのどれも、次の形のオブジェクトを1つ返すファイルとして作る。例はMIDI書き出し。

```js
/** @type {import('../core/types.js').ExportConnector} */
export const midiExport = {
  id: 'midi-export',
  name: 'MIDIファイル',
  kind: 'export',

  /** 使えるかどうかと、使えない時の理由 */
  async isAvailable() {
    return { ok: true };
  },

  /** 曲データを受け取り、ファイルと注意書きを返す */
  async run(song) {
    const bytes = toMidiBytes(song);
    return {
      file: { name: `${song.meta.title}.mid`, type: 'audio/midi', bytes },
      warnings: ['コード進行はMIDIには含まれません'],
    };
  },
};
```

| 種類 | runが受け取るもの | runが返すもの |
| --- | --- | --- |
| 取り込み | ファイル | 曲データと注意書き |
| 書き出し | 曲データ | ファイルと注意書き |
| エンジン | 曲データと対象範囲 | 結果(音声など)と注意書き |

## 操作の共通化

曲への変更はすべて「操作」として定義し、画面もMCPも同じ操作を呼ぶ。破綻防止の検査、revisionの更新、「元に戻す」の記録が1か所で済み、画面とMCPで挙動がずれない。

| 操作 | 内容 |
| --- | --- |
| 曲を作る | 雰囲気とテンポから叩き台を作る、または取り込んだ曲データを登録する |
| 部品を差し替える | 部品1つのコード進行やパートを別案に置き換える |
| 並び順を変える | 部品の追加、削除、並べ替え |
| 部品の区切りを直す | 区切り位置の調整と名前の変更(MIDI取り込み後に使う) |
| 歌詞を入れる | 並び順の1か所に歌詞を割り当てる(P2) |
| 曲の設定を変える | 曲名、テンポ、キー、パートの楽器と音量 |
| 元に戻す | 直前の操作を取り消す |

## コードの置き場

曲データの検査と操作は、画面にもCloudflare Workersにも依存しない素のJavaScriptとして書き、ブラウザとWorkersの両方から同じファイルを使う。

| 場所 | 中身 | 動く場所 |
| --- | --- | --- |
| src/core | 曲データの型、検査、操作、別案を作るルール | ブラウザとWorkersの両方 |
| src/connectors | 接続口(midi、audio、voicevox)と登録簿 | ブラウザ |
| src/audio | Web Audio APIによる再生と楽器の音 | ブラウザ |
| src/ui | 画面 | ブラウザ |
| worker | 保存用API、MCPサーバー、OAuth、ログイン | Workers |

## 確定した点

- 「元に戻す」はアプリを開いている間なら何手でも戻せる。閉じたら履歴は消える
- MCPには上の操作をすべて許可する。曲の削除だけはMCPに出さず、画面からのみ行える
