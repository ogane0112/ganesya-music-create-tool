# 初心者用音楽作成ソフト 要件定義

2026-11-16 時点

## コンセプト

AIが叩き台を出し、自分は「聴いて選ぶ・差し替える」だけで歌入りの1曲が完成する、音楽知識ゼロの人向けの作曲ソフト。

**成功基準**:音楽知識ゼロの自分が、歌入りの曲を最後まで作って音声ファイルに書き出せること。

目指す曲調はJ-POP(米津玄師のような作風)。特定の曲をコピーするのではなく、コード進行の傾向・リズムの癖・転調といった特徴を部品として持たせる。

**位置づけ**:音楽に関連するものをすべて繋ぐハブ。中心に「曲データ」を置き、AI(MCP)・歌声エンジン(VOICEVOX)・他の作曲ソフト(MIDI)・音声ファイルを、それぞれ差し替え可能な接続口として繋ぐ。新しい道具が出てきたら接続口を足すだけで済む作りにする。

## 決定事項

| 項目 | 決定 | 内容 |
| --- | --- | --- |
| 作り方の核 | ハイブリッド | AIが叩き台を出し、自分が部品単位で差し替え・調整する |
| ゴール | 自分が1曲完成させる | まず自分用。最後まで作り切れることが基準 |
| ボーカル | 合成音声で歌わせる | 歌詞を入れて歌声合成まで行う |
| 動作環境 | PWA | iPadとPCに対応 |
| 歌詞 | ハイブリッド | AIが案を出し、自分が行単位で選ぶ・書き換える |
| MCP | 対応する | AIから曲の読み書きと生成ができる |
| 書き出し形式 | WAVとMIDI(MP3は後で追加) | よくある形式で出し、他のソフトでも使えるようにする |
| 生成方式 | アプリ内ルール+MCP | アプリ内のルールで即座に別案を出し、MCP経由でClaudeにも案を作らせる |
| 別案の数 | 3案 | 気に入らなければ出し直す |
| 保存と同期 | オンライン前提 | サーバーのデータを正とし、オフライン編集は持たない |
| MIDI読み込み | 最初から読み書き両方 | 他ソフトと行き来できるようにする |
| バックエンド | Cloudflare | PagesでPWA配信、WorkersでAPIとMCP、D1に曲データ、R2に音声ファイル |
| MCP認証 | OAuth | Claudeのアプリからコネクタとして繋ぐ |
| 楽器の音源 | 10種前後 | ピアノ・ギター・ベース・ドラム・シンセにストリングスなどを足す |
| 雰囲気 | 4種 | 切ない、疾走感、ダーク・不穏、明るい・爽やか |
| フロントエンド | バニラ+Vite | フレームワークを使わない。長く使えるようにするため |
| 歌声エンジン | VOICEVOX | ローカルで起動したVOICEVOXをアプリから呼び出す。サーバーには置かない |
| 位置づけ | 音楽のハブ | 曲データを中心に、外部の道具を差し替え可能な接続口で繋ぐ |
| 音の鳴らし方 | ブラウザ標準を直接 | Web Audio APIを直接使い、外部ライブラリに依存しない。再生タイミングの管理は自作する |
| 言語 | JavaScript+JSDoc | 素のJavaScriptにコメントで型を書く。変換なしでブラウザが読める |
| 楽器の内訳 | バンド+彩りの10種 | ピアノ、アコギ、エレキ(クリーン)、エレキ(歪み)、ベース、ドラム、ストリングス、シンセリード、シンセパッド、ベル |
| MIDI取り込みの区切り | 自動で区切り自分で名付け | 一定の小節数で自動的に区切り、区切り位置の調整とAメロ・サビの名付けは自分で行う |
| 別案の保存 | 保存しない | 選んだ案だけ残し、「元に戻す」でやり直す |
| P1の絞り込み | 4/4拍子・テンポ変更なし・転調なし | 曲データに項目は持つが、画面では変えられない |
| 歌メロ | 1パートのみ | ハモリは持たない |
| ログイン | パスキー+Cloudflare Access | アプリのログイン(パスキー)が誰の曲かを決め、MCPの本人確認も兼ねる。Accessは画面の外側の門で、公開時に外す |
| 保存方法 | 自動保存と保存ボタンの切り替え | 設定で切り替える。初期値は自動保存 |

## 機能要件

| # | 機能 | 内容 | フェーズ |
| --- | --- | --- | --- |
| F1 | 叩き台生成 | 雰囲気(切ない、疾走感、ダーク・不穏、明るい・爽やかの4種)とテンポを選ぶと、コード進行・メロディ・ベース・ドラムが出る | P1 |
| F2 | 曲構成 | Aメロ・Bメロ・サビをブロックとして並べる | P1 |
| F3 | 差し替え編集 | ブロック単位で別案を3つ出し、聴き比べて選ぶ。音符を直接触らなくてよい | P1 |
| F4 | 破綻防止 | キーとスケールを固定し、外れた音はそもそも置けない | P1 |
| F5 | 再生 | 全体・ブロック単位で再生、ループ再生 | P1 |
| F6 | 保存 | 途中から再開できる。MCPから読み書きするため、曲データはサーバー側に保存する(オンライン前提) | P1 |
| F7 | 書き出し | 音声はWAV(MP3は後で追加)、音符データはMIDI(.mid)。MIDIは他の作曲ソフトでそのまま開ける。MIDIの読み込みにも対応する | P1 |
| F8 | 歌詞(ハイブリッド) | 下記参照 | P2 |
| F9 | 歌声 | 歌詞をメロディに割り当て、合成音声で歌わせる | P2 |
| F10 | フル尺・音量バランス | 1コーラスからフル尺へ拡張、パートごとの音量調整 | P3 |
| F11 | MCP | AI(Claudeなど)から曲を操作できる。曲の一覧・読み取り、叩き台の作成、ブロックの差し替え、歌詞の書き込み(P2)、MIDIの書き出し | P1 |
| F12 | 元に戻す | 直前の操作を取り消す。別案を選び直したい時に使う | P1 |

### F8 歌詞(ハイブリッド)の中身

1. テーマやキーワードを入力する(例:夜、別れ、夏の終わり)
2. AIがブロックごとに歌詞案を出す
3. 行単位で「別案を出す」か「自分で書き換える」を選べる
4. 全部自分で書くことも、全部AI案のままにすることもできる
5. メロディの音数に合っているかを表示する(字余り・字足らずを警告)

音数合わせが要になる。メロディの音の数と歌詞の文字数(モーラ数)が合わないと歌わせられないため、AI案は最初から音数に合わせて生成し、手書き時はズレを知らせる。

## 非機能要件

- PWAとして動作し、iPadとPCにインストールできる
- タッチ操作とマウス操作の両方で使える
- オンライン前提で動作する。オフライン編集には対応しない
- 音楽用語を画面に出さない。出す場合は一言の説明を添える
- 利用者は自分1人。共有機能は持たない。ただし将来の公開に備え、アプリのログインを持ち、曲に持ち主を記録する

## フェーズ

1. **P1 歌なしで1コーラス完成**:叩き台生成、構成、差し替え、再生、保存、書き出し(F1〜F7、F11、F12)
2. **P2 歌詞と歌声**:歌詞ハイブリッドと歌声合成(F8、F9)。着手前に歌声合成の技術調査を行う
3. **P3 フル尺と仕上げ**:フル尺への拡張と音量バランス調整(F10)

## リスクと前提

- **「神曲」はツールでは保証できない。** 保証できるのは「破綻しない」まで。良し悪しは選ぶ耳で決まるため、聴き比べ(F3)を核に据える。
- **歌声合成が最大の技術リスク。** ブラウザ単体では重く、サーバーか外部エンジンとの連携になる見込み。P2着手前に方式を調査して決める。
- **歌詞の音数合わせは難所。** AI案が音数どおりに出るとは限らないため、ズレの検出と再生成の仕組みが必要。
- **作風の再現は特徴の部品化で行う。** 既存曲のメロディや歌詞そのものは使わない。

## 接続口(ハブ設計)

外部の道具はすべて「接続口」として本体から切り離し、後から足せる設計にする。P1・P2で作るのは上の4つで、下の4つは将来繋げられるよう備えるだけで今は作らない。

| 繋ぐ相手 | 受け渡すもの | 時期 |
| --- | --- | --- |
| AI(Claudeなど) | MCPで曲データを読み書き | P1 |
| 他の作曲ソフト | MIDIの読み書き | P1 |
| 音声ファイル | WAVの書き出し(MP3は後で追加) | P1 |
| 歌声エンジン(VOICEVOX) | 音符と歌詞を渡し、歌声の音声を受け取る | P2 |
| DAW | MIDIに加え、パートごとに分けた音声ファイル | 将来 |
| 楽譜ソフト | MusicXML(楽譜の標準形式) | 将来 |
| 動画編集 | 完成音源と、歌詞の表示タイミング(字幕ファイル) | 将来 |
| 音楽配信 | 完成音源と、曲名・作者名・ジャケット画像などの情報 | 将来 |

将来の接続に備えて、曲データには最初から次を持たせる。MIDIだけでは表せない情報で、後から足すと作り直しになるため。

- 曲の構成(Aメロ・Bメロ・サビの区切り)
- コード進行、キー、テンポ
- パートごとの音符と楽器
- 歌詞と、どの音符にどの文字が乗るか
- 曲名・作者名などの情報

## 歌声合成エンジンの候補

VOICEVOXに決定。エンジンがHTTPサーバーとして動くため、アプリから呼び出す形に最も組み込みやすい。2026-11-16時点のWeb検索による調査で、実機での検証はまだしていない。

| 候補 | 特徴 | 組み込みやすさ | 懸念 |
| --- | --- | --- | --- |
| [VOICEVOX](https://github.com/VOICEVOX/voicevox_engine) | 無料。v0.16.0でソング機能がプロトタイプとして追加され、ビブラートや息継ぎが自動で付く([窓の杜](https://forest.watch.impress.co.jp/docs/news/1567478.html)) | 高い。エンジンの実態がHTTPサーバーで、Dockerイメージもある | 動かすマシンが必要。声ごとにキャラクターの利用規約がある。歌唱APIの詳細は要検証 |
| [NEUTRINO](https://dic.nicovideo.jp/a/neutrino(%E6%AD%8C%E5%A3%B0%E5%90%88%E6%88%90%E3%82%A8%E3%83%B3%E3%82%B8%E3%83%B3)) | フリーウェア。MusicXML形式の楽譜から歌い方を推定して合成する | 中。ファイルを渡して実行する形のため、API化は自前で作る | 利用規約は未確認 |
| [OpenUtau+DiffSinger](https://dic.pixiv.net/a/DiffSinger) | オープンソース。有志制作の歌声モデルが多く、日本語対応モデルもある | 低い見込み。編集ソフトとして使う前提の作り | モデルごとに規約が異なる |
| クラウドの歌声API | MIDIと歌詞を送ると歌声が返るとうたうサービスがある | 高い。サーバー不要でCloudflareから直接呼べる | 有料。日本語の品質とサービスの継続性は未確認 |

エンジンは後から差し替えられるよう、アプリ側は「音符と歌詞を渡すと音声が返る」という窓口だけを持つ設計にする。
