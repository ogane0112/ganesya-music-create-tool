# 曲データ設計

曲データは「1曲=1つのJSON」とし、部品(Aメロ・サビなど)の定義と並び順を分けて持つ。末尾の3点を含めて確定済み。

## 全体の形

| 項目 | 中身 | 何のためか |
| --- | --- | --- |
| formatVersion | 形式の版番号(1から) | 将来形を変えても古い曲を読めるようにする |
| revision | 保存のたびに増える番号 | アプリとMCPが同時に書いた時の上書き事故を防ぐ |
| meta | 曲名、作者名、作成日時、更新日時 | 一覧表示、音楽配信 |
| tempo / key / timeSignature | テンポ、キー、拍子 | 破綻防止、MIDI、楽譜 |
| mood | 選んだ雰囲気 | 別案を出す時の手がかり |
| tracks | パートの一覧(楽器、役割、音量) | 再生、DAW向け書き出し |
| sections | 部品の定義(コード進行とパートごとの音符) | 差し替え編集 |
| arrangement | 部品の並び順と、その箇所の歌詞 | 曲構成、歌声、字幕 |
| extensions | 接続口ごとの追加情報の置き場 | 本体の形を変えずに接続口を足す |

## 設計上の判断

1. **部品の定義と並び順を分ける。** サビを2回使う時、定義は1つで、並び順に2回書く。サビを直せば両方に反映される。
2. **歌詞は並び順の側に持つ。** 1番と2番は同じメロディで歌詞が違う。部品の側に持つと2番の歌詞が書けない。
3. **時間はティックで表す。** 1拍=480ティック。MIDIと同じ数え方なので変換で誤差が出ない。位置は部品の先頭から数えるため、部品を並べ替えても中身を書き換えなくてよい。
4. **音符にIDを振る。** 歌詞の1文字をどの音符に乗せるかをIDで指すため。
5. **コード進行は音符と別に持つ。** 別案生成の土台になる。MIDIから読み込んだ曲はコードが空になる(キーによる破綻防止は効く)。
6. **部品ごとにキーを上書きできる項目を持つ。** サビでの転調に備える。P1の画面では使わない。
7. **知らない項目は消さずに残す。** 新しい版や接続口が足した項目を、古い画面が保存時に消さないようにする。

## 例

Aメロ1つだけの最小の曲。`1920`は480ティック×4拍で1小節、`pitch`の`69`はMIDIの音番号で「ラ」を指す。

```json
{
  "formatVersion": 1,
  "revision": 12,
  "meta": { "title": "無題の曲", "artist": "", "createdAt": "2026-11-16T02:00:00Z", "updatedAt": "2026-11-16T02:30:00Z" },
  "tempo": 96,
  "key": { "tonic": "A", "mode": "minor" },
  "timeSignature": [4, 4],
  "mood": "setsunai",
  "tracks": [
    { "id": "t1", "role": "vocal", "instrument": "piano", "volume": 0.8 },
    { "id": "t2", "role": "chords", "instrument": "acoustic-guitar", "volume": 0.6 }
  ],
  "sections": [
    {
      "id": "s1", "name": "Aメロ", "kind": "verse", "bars": 8,
      "chords": [ { "start": 0, "length": 1920, "symbol": "Am" } ],
      "parts": {
        "t1": [ { "id": "n1", "start": 0, "length": 480, "pitch": 69, "velocity": 90 } ]
      }
    }
  ],
  "arrangement": [
    { "id": "a1", "sectionId": "s1", "lyrics": [ { "noteId": "n1", "kana": "よ" } ] }
  ],
  "extensions": {}
}
```

## 接続口との対応

| 接続口 | 曲データのどこを使うか |
| --- | --- |
| MIDI書き出し | 音符を並び順どおりに展開する。部品の区切りはマーカー、歌詞は歌詞イベントとして入れる |
| MIDI読み込み | 音符をtracksに入れ、8小節ごとにsectionsへ自動分割する。コードは空 |
| VOICEVOX | 歌メロのパートの音符と、arrangementの歌詞(かな) |
| MCP | 曲データ全体の読み取りと、部品単位の書き込み。revisionで衝突を検出する |
| 楽譜ソフト(将来) | 音符、コード、歌詞、キー、拍子 |
| 動画編集(将来) | arrangementの歌詞と、テンポから計算した表示時刻 |
| 音楽配信(将来) | meta |

## 保存

Cloudflare D1に1曲1行で保存する。列はid、owner_id(持ち主)、title、updated_at、revision、data(JSON全体)。書き出した音声ファイルはR2に置く。

保存時に手元のrevisionとサーバーのrevisionが違えば保存を拒否し、最新を読み直す。アプリを開いたままClaudeがMCPで書き換えた場合に、片方の変更が黙って消えるのを防ぐ。

## 確定した点

- 別案(3案)は曲データに保存せず、選んだ案だけを残す。代わりに「元に戻す」機能を持つ
- P1は4/4拍子・曲中のテンポ変更なし・転調なしに絞る(項目は持つが画面では変えられない)
- 歌メロは1パートのみで、ハモリは持たない
