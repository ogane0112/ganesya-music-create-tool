## スプリント1の結果

- `npm run dev` で開発サーバー、`npm run check` で型チェックとテストがまとめて走る
- `src/core/types.js` 曲データ・失敗・接続口の型
- `src/core/theory.js` キーに合う音、コード名から構成音、ティックと秒
- `src/core/validate.js` 形の検査、キーから外れた音の検出(取り込み時は注意書きにとどめる)、知らない項目は残す
- `src/core/operations.js` 曲を作る・部品を差し替える・並び順を変える・区切りを直す・曲の設定を変える。すべて新しい曲データを返し、元は変えない
- `src/core/history.js` 何手でも戻せる「元に戻す」

### 決めたこと(設計書に書かれていなかった細部)

- 雰囲気のIDは `setsunai`(切ない)・`shissou`(疾走感)・`dark`(ダーク・不穏)・`akarui`(明るい・爽やか)
- キーに合う音は自然な長音階・短音階の7音。ドラムのパートは調べない
- 操作で検査を厳しくするのは「変えた部品」だけ。MIDI取り込み曲の、関係ない部品の外れた音のせいで操作できなくなるのを防ぐ
- 並び順から外して使われなくなった部品の定義は消す(「元に戻す」で戻せる)
- キーを変えると音符とコードも一緒に移す。暗い⇔明るいの変更は平行調(音の並びが同じキー)を基準にする
- テンポは40〜240。画面の3段階は ゆっくり78・ふつう100・はやい150
- 接続口の run は `{ ok, value, warnings }` / `{ ok:false, error }` の共通の結果形式で返す
- 「元に戻す」で戻した曲の revision は古いことがあるので、保存する側がサーバーの最新 revision を付けて送る

## スプリント2の結果

- `npm run dev` で開く試作画面で、雰囲気と速さを選ぶ→叩き台→全体・部品ごとに聴く→別案3つを聴き比べて選ぶ→元に戻す、までできる
  - 並べ替え・部品をもう一度使う・外す、パートの楽器・音量・消音も試せる
  - 保存はまだ端末の中だけ(1曲)。サーバー保存はスプリント4
- `src/core/composer/` 叩き台のルール(B6)
  - 雰囲気ごとにコード進行の候補(王道進行 4-5-3-6、小室進行 6-4-5-1、カノン進行など)、伴奏の弾き方、ドラムの型、楽器の組み合わせを持つ(`styles.js`)
  - メロディは2小節×4フレーズを「a a' b a''」のように繰り返して作る。強い拍はコードの音に寄せ、サビほど高い音域
  - キーに合う音の並びの中で作るので、外れた音は出ない
- `src/core/alternatives.js` 別案(B7)。メロディ/コード進行/伴奏/全部。コード進行の別案は今のメロディに一番合うものを選ぶ
- `src/core/timeline.js` 並び順どおりに音符を並べる(再生・WAV・MIDIで共通)
- `src/audio/player.js` 再生(C1)。Web Audio の時計で少し先まで予約する方式。ループ・部品単位の再生
- `src/audio/instruments/` 楽器10種をブラウザ上で合成(C2)。ギターは弦をはじく計算(Karplus-Strong)、ベルはFM合成。登録簿で差し替えられる
- `src/audio/offline.js` `src/audio/wav-encode.js` 曲全体をWAVにする(C3を前倒し。耳での確認用のサンプルを作るため)
- 雰囲気4種の叩き台のWAVを作ってチャットで渡した(容量が大きいのでリポジトリには入れない)

- 楽器の音色で特に気になるもの(仮の音なので、入手元が決まれば差し替える)

気になった点を伝えてもらえれば、`src/core/composer/styles.js` の候補や重みを直す。

## スプリント2.6(「WAVが遅い」「音がシンプルすぎて眠い」を受けて)

### WAVの書き出しを速くした(45秒の曲で 約74秒 → 約3秒、テスト用ブラウザで計測)

- 原因:合成の部品を音符ごとに作っていた(スーパーソーは1音で部品14個)。テスト環境では、短い音を1500個貼るだけでも7秒かかる
- `src/audio/note-cache.js` 音符の作り置き
  - 楽器・高さ・長さ(10ミリ秒単位)・強さ(4段階)が同じ音は一度だけ合成して録音しておき、2回目からは貼るだけにする
  - ドラムは2通り作って交互に使う
  - 再生もWAVも同じ作り置きを使うので、聴こえ方は同じ
- `src/audio/offline.js` WAVは音符をパートごとにJavaScriptで足し合わせ、残響などのエフェクトだけをWeb Audioに通す
  - バスドラムに合わせたうねりも同じ曲線で計算する
- 再生ボタンを押すと、初めての音を作り置きする間「準備中…」と出る(約1.5秒)
- 試作画面に「WAVで保存」を付けた。進み具合を%で出す

### 音を賑やかにした

- 新しいパート「彩り」(全部の雰囲気)
  - Aメロ・Bメロでは、メロディが2拍以上休む所に短い駆け上がり・駆け下り
  - サビでは高い所で対旋律
- 編曲の起伏(`src/core/composer/arrange.js`)
  - Aメロの前半は静か(スネアを縁打ちに)、後半から本調子
  - Bメロ:頭でシンバル、終わり2小節で上がっていく効果音
  - Bメロの最後の1拍は歌以外が止まって溜める(ブレイク)。直前に全員で「ジャン」
  - サビの後半はハイハットを細かく。EDMは手拍子を重ねる
  - ドラムに小さなスネア(ゴースト)と開いたハイハットで揺れ
- 音作り
  - メロディ・リフ・彩りに山びこ(付点8分のディレイ、左右に跳ねる)
  - バスドラムをパンチのある音に
  - 音割れを防ぐリミッターを最後に入れた
- ドラムの番号:27 を「上がっていく効果音」、39 を手拍子に使う(MIDIに書き出すと 27 は High Q という別の音になる。D2で注意書きにする)
- 別案:メロディの別案では、彩り(メロディの合間を埋める)も一緒に作り直す

- テスト用ブラウザでは、日本語のファイル名でダウンロードすると「download」という名前になる。実機のChrome・Safariで確かめる

## デプロイ(Cloudflare Workers)

- 公開先: https://ganesya-music.t4qjpmb66z.workers.dev (試作画面。誰でも開ける状態。Cloudflare Access は E5 で掛ける)
- `npm run deploy` で ビルド → 画面のファイルを Worker に埋め込む → `wrangler deploy`
- Cloudflare Pages は Workers に統合されたため、Workers に置いた(設計のAPI・MCPも Workers なので同じ所にまとまる)
- この開発環境では Workers の静的ファイルのアップロードが通らない(アップロード用の一時的な鍵を中継が上書きするため)ので、画面のファイルを `scripts/embed-assets.mjs` でスクリプトに埋め込んでいる。音源ファイルなど大きなものを配る時は、R2 に置くか、手元のPCから静的ファイルとして配る方式に切り替える
- Cloudflare の API トークン(Pages/Workers の編集権限)は、この開発環境のネットワーク設定に保存した

- メニュー(⋯):同じ雰囲気で作り直す、音声ファイル(WAV)で保存、新しい曲を作る
- 曲名は上の欄をそのまま書き換える
- 用語:「コード進行」→「和音の流れ」、「全部」→「まるごと」
- iPad(820px)・スマホ(390px、ダーク)・PC(1280px)で一連の操作をブラウザで自動確認。横スクロールのはみ出しなし

## スプリント3(MCPを前倒し:「AIが米津玄師風の神曲を作れるようにしたい」)

タスク: E1(保存用API)、E3(MCP 9ツール)、D1・D2(接続口の登録簿とMIDI書き出し)、F2・F5の一部(曲一覧・自動保存)。E2・E4(パスキー・OAuth)は未着手で、仮の合言葉で代用している。

### AIの作り方(設計の考え方)

- AIが書くのは「コード進行」と「メロディ」。伴奏(和音・ベース・ドラム・背景・彩り)は、書かれたコード進行に合わせてルールが付ける(`src/core/authoring.js`)
- かんたん記法(`src/core/notation.js`):メロディ `E5:1 D5:0.5 r:0.5 | C5:2`、コード `Am7:4 F:2 G:2`。長さは拍、3連符は `1/3`
- 手引き(`worker/guide.js`、get_format_guide):書き方、決まり、良い曲にする作り方、米津玄師さんの曲によく見られる特徴(進行・メロディ・リズム・構成)を部品として記載。既存曲のメロディ・歌詞は使わない
- 失敗は「どの部品の何小節目の何拍目の、どの音が、どのコードに合わないか」を返し、AIが自分で直せるようにした

### 破綻防止の決まりを変えた(要件 F4 の変更)

- 前:キーから外れた音は置けない
- 今:**キーの音か、その時鳴っているコードの音**なら置ける。キーにもコードにも合わない音は置けない
- 理由:借用和音・セカンダリードミナント(例:Aマイナーでの E7、Gm7→C7)が米津風の要で、前の決まりでは一切使えなかった
- MIDI取り込みの曲は今までどおり断らず、注意書きにする

### サーバー

- Cloudflare D1 `ganesya-music`(`migrations/0001_songs.sql`)。1曲1行、revision が合う時だけ上書き
- 保存用API(`worker/api.js`):外部設計の表どおり。revision 不一致で 409、失敗は `{ code, message, hint }`
  - キーから外れた音は保存用APIでは断らない(操作の中で確かめている。MIDI取り込みの曲を保存できる必要があるため)。形が正しくないものは 422
- MCP(`worker/mcp.js`、`worker/tools.js`):Streamable HTTP(状態なし)。ツール9個は外部設計どおり。曲の削除は出さない
  - generate_alternatives は seed と index を返し、replace_section の alternative に渡すと採用できる(別案を保存しないため)
- **仮の本人確認**:Worker の秘密の値 ACCESS_KEY(合言葉)。保存用APIは `Authorization: Bearer`、MCP は URL に入れる(`/mcp/<合言葉>`)
  - 設計(パスキー+OAuth+Cloudflare Access)とは違う。E2・E4・E5 で置き換える。それまでは、合言葉を知っている人は誰でも曲を読み書きできる

### 画面

- 合言葉の入力(一度入れれば端末が覚える)→ 曲一覧(開く・削除・新しい曲)→ 編集
- 操作のたびに自動保存。右上に「保存済み/保存中…/未保存」
- 開いている曲が他(AI)で更新されたら、8秒以内に自動で読み込む。保存がぶつかった時は「最新を読み込む」を出す
- 曲一覧に「AIに曲を作ってもらう」手順と、コネクタに登録するURL(コピーボタン付き)

### 確かめたこと

- テスト95個(MCPの一連の流れ、手引きの作例がそのまま通ること、を含む)
- 手元(wrangler dev + ローカルD1)で、合言葉→一覧→開く→再生→自動保存→AIの変更の自動読み込み→衝突→新規作成 をブラウザで自動確認
- 本番で、合言葉なし・違う合言葉が 401 になること、MCP の initialize、create_song(「宵の残り火」を作成)を確認
- まだ確かめていない:Claude のアプリからコネクタとして実際につなぐこと(利用者の操作が必要)

```sh
npm run dev          # 画面。/api と /mcp は 8787 に回る
```

## スプリント3.5(「MCPはOAuthじゃないの?」「音が安っぽい」を受けて)

### MCP を OAuth にした(E4)

- 前回の「URLに合言葉を入れる」方式は、設計(OAuth)と違う近道だったのでやめた。`/mcp/<合言葉>` はもう通らない
- `worker/oauth.js`:OAuth 2.1 の認可コード+PKCE(S256)、クライアントの自動登録、許可証の更新(使うたびに入れ替え)
  - 許可証は1時間、更新用は60日、認可コードは5分・1回限り。どれもハッシュで保存(`migrations/0002_oauth.sql`)
  - 許可の画面(`/oauth/authorize`):何を許すかを表示し、本人確認をして「許可する」
- コネクタに登録するURLは `https://ganesya-music.t4qjpmb66z.workers.dev/mcp`(秘密は入らない)
- **まだ仮の部分**:許可の画面と保存用APIの本人確認は合言葉。パスキーのログイン(E2)を作って置き換える。Cloudflare Access(E5)も未着手
- 確かめたこと:テスト(登録→許可→交換→更新、違う合言葉、PKCE違い、コードの再利用、未登録の相手、違う戻り先)。本番で 401 → 案内 → 登録 → 許可 → 許可証 → MCP の一連
- まだ確かめていない:Claude のアプリから実際にコネクタとしてつなぐこと

### 楽器を録音の音にした(C2 の差し替え、未決事項「音源の入手元」を決定)

- 音源:**FluidR3_GM**(MITライセンス。商用可・改変可・再配布可。`THIRD_PARTY.md` に表示)
- 録音の音にした楽器:ピアノ、アコースティックギター、エレキ(クリーン)、エレキ(歪み)、ベース、ストリングス、ベル(オルゴール)、ドラム
- 合成のままの楽器:シンセリード、シンセパッド、シンセ(厚い音)、サビ前の効果音。もともと電子音なので合成で作る
- 作り方(`scripts/build-samples.py`):fluidsynth で3半音おきに1音ずつ録音 → MP3(モノラル96kbps)→ 楽器ごとに1ファイル(.pack)。全部で5.3MB
- 鳴らし方(`src/audio/instruments/sampled.js`):一番近い録音を、再生の速さを変えて目的の高さにする。MP3の頭の無音は読み込み時に飛ばす(音の出だしのずれは10ミリ秒以内)
- 使う楽器の音源だけを、最初の再生の前に読み込む(1曲で2〜4MB)。読み込めない時は合成の音で鳴る
- 置き場:Cloudflare KV(`/sounds/v1/…`)。設計では R2 だが、このアカウントでは R2 が有効になっていないため。R2 を有効にしたら移す
- 音源を作り直す:`npm run sounds:build` → `npm run sounds:upload`(手元は `sounds:upload:local`)
