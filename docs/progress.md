## スプリント1の結果

- `npm run dev` で開発サーバー、`npm run check` で型チェックとテストがまとめて走る
- `src/core/types.js` 曲データ・失敗・接続口の型
- `src/core/theory.js` キーに合う音、コード名から構成音、ティックと秒
- `src/core/validate.js` 形の検査、キーから外れた音の検出(取り込み時は注意書きにとどめる)、知らない項目は残す
- `src/core/operations.js` 曲を作る・部品を差し替える・並び順を変える・区切りを直す・曲の設定を変える。すべて新しい曲データを返し、元は変えない
- `src/core/history.js` 何手でも戻せる「元に戻す」

### 決めたこと(設計書に書かれていなかった細部)

- 雰囲気のIDは `setsunai`(切ない)・`shissou`(疾走感)・`dark`(ダーク・不穏)・`akarui`(明るい・爽やか)
- キーに合う音は自然な長音階・短音階の7音。ドラムのパートは調べない
- 操作で検査を厳しくするのは「変えた部品」だけ。MIDI取り込み曲の、関係ない部品の外れた音のせいで操作できなくなるのを防ぐ
- 並び順から外して使われなくなった部品の定義は消す(「元に戻す」で戻せる)
- キーを変えると音符とコードも一緒に移す。暗い⇔明るいの変更は平行調(音の並びが同じキー)を基準にする
- テンポは40〜240。画面の3段階は ゆっくり78・ふつう100・はやい150
- 接続口の run は `{ ok, value, warnings }` / `{ ok:false, error }` の共通の結果形式で返す
- 「元に戻す」で戻した曲の revision は古いことがあるので、保存する側がサーバーの最新 revision を付けて送る

## スプリント2の結果

- `npm run dev` で開く試作画面で、雰囲気と速さを選ぶ→叩き台→全体・部品ごとに聴く→別案3つを聴き比べて選ぶ→元に戻す、までできる
  - 並べ替え・部品をもう一度使う・外す、パートの楽器・音量・消音も試せる
  - 保存はまだ端末の中だけ(1曲)。サーバー保存はスプリント4
- `src/core/composer/` 叩き台のルール(B6)
  - 雰囲気ごとにコード進行の候補(王道進行 4-5-3-6、小室進行 6-4-5-1、カノン進行など)、伴奏の弾き方、ドラムの型、楽器の組み合わせを持つ(`styles.js`)
  - メロディは2小節×4フレーズを「a a' b a''」のように繰り返して作る。強い拍はコードの音に寄せ、サビほど高い音域
  - キーに合う音の並びの中で作るので、外れた音は出ない
- `src/core/alternatives.js` 別案(B7)。メロディ/コード進行/伴奏/全部。コード進行の別案は今のメロディに一番合うものを選ぶ
- `src/core/timeline.js` 並び順どおりに音符を並べる(再生・WAV・MIDIで共通)
- `src/audio/player.js` 再生(C1)。Web Audio の時計で少し先まで予約する方式。ループ・部品単位の再生
- `src/audio/instruments/` 楽器10種をブラウザ上で合成(C2)。ギターは弦をはじく計算(Karplus-Strong)、ベルはFM合成。登録簿で差し替えられる
- `src/audio/offline.js` `src/audio/wav-encode.js` 曲全体をWAVにする(C3を前倒し。耳での確認用のサンプルを作るため)
- 雰囲気4種の叩き台のWAVを作ってチャットで渡した(容量が大きいのでリポジトリには入れない)

気になった点を伝えてもらえれば、`src/core/composer/styles.js` の候補や重みを直す。

## スプリント2.6(「WAVが遅い」「音がシンプルすぎて眠い」を受けて)

### WAVの書き出しを速くした(45秒の曲で 約74秒 → 約3秒、テスト用ブラウザで計測)

- 原因:合成の部品を音符ごとに作っていた(スーパーソーは1音で部品14個)。テスト環境では、短い音を1500個貼るだけでも7秒かかる
- `src/audio/note-cache.js` 音符の作り置き
  - 楽器・高さ・長さ(10ミリ秒単位)・強さ(4段階)が同じ音は一度だけ合成して録音しておき、2回目からは貼るだけにする
  - ドラムは2通り作って交互に使う
  - 再生もWAVも同じ作り置きを使うので、聴こえ方は同じ
- `src/audio/offline.js` WAVは音符をパートごとにJavaScriptで足し合わせ、残響などのエフェクトだけをWeb Audioに通す
  - バスドラムに合わせたうねりも同じ曲線で計算する
- 再生ボタンを押すと、初めての音を作り置きする間「準備中…」と出る(約1.5秒)
- 試作画面に「WAVで保存」を付けた。進み具合を%で出す

### 音を賑やかにした

- 新しいパート「彩り」(全部の雰囲気)
  - Aメロ・Bメロでは、メロディが2拍以上休む所に短い駆け上がり・駆け下り
  - サビでは高い所で対旋律
- 編曲の起伏(`src/core/composer/arrange.js`)
  - Aメロの前半は静か(スネアを縁打ちに)、後半から本調子
  - Bメロ:頭でシンバル、終わり2小節で上がっていく効果音
  - Bメロの最後の1拍は歌以外が止まって溜める(ブレイク)。直前に全員で「ジャン」
  - サビの後半はハイハットを細かく。EDMは手拍子を重ねる
  - ドラムに小さなスネア(ゴースト)と開いたハイハットで揺れ
- 音作り
  - メロディ・リフ・彩りに山びこ(付点8分のディレイ、左右に跳ねる)
  - バスドラムをパンチのある音に
  - 音割れを防ぐリミッターを最後に入れた
- ドラムの番号:27 を「上がっていく効果音」、39 を手拍子に使う(MIDIに書き出すと 27 は High Q という別の音になる。D2で注意書きにする)
- 別案:メロディの別案では、彩り(メロディの合間を埋める)も一緒に作り直す

### 気づいたこと

- テスト用ブラウザでは、日本語のファイル名でダウンロードすると「download」という名前になる。実機のChrome・Safariで確かめる

## デプロイ(Cloudflare Workers)

- 公開先: https://ganesya-music.t4qjpmb66z.workers.dev (試作画面。誰でも開ける状態。Cloudflare Access は E5 で掛ける)
- `npm run deploy` で ビルド → 画面のファイルを Worker に埋め込む → `wrangler deploy`
- Cloudflare Pages は Workers に統合されたため、Workers に置いた(設計のAPI・MCPも Workers なので同じ所にまとまる)
- この開発環境では Workers の静的ファイルのアップロードが通らない(アップロード用の一時的な鍵を中継が上書きするため)ので、画面のファイルを `scripts/embed-assets.mjs` でスクリプトに埋め込んでいる。音源ファイルなど大きなものを配る時は、R2 に置くか、手元のPCから静的ファイルとして配る方式に切り替える
- Cloudflare の API トークン(Pages/Workers の編集権限)は、この開発環境のネットワーク設定に保存した

## スプリント3(MCPを前倒し:「AIが米津玄師風の神曲を作れるようにしたい」)

タスク: E1(保存用API)、E3(MCP 9ツール)、D1・D2(接続口の登録簿とMIDI書き出し)、F2・F5の一部(曲一覧・自動保存)。E2・E4(パスキー・OAuth)は未着手で、仮の合言葉で代用している。

### AIの作り方(設計の考え方)

- AIが書くのは「コード進行」と「メロディ」。伴奏(和音・ベース・ドラム・背景・彩り)は、書かれたコード進行に合わせてルールが付ける(`src/core/authoring.js`)
- かんたん記法(`src/core/notation.js`):メロディ `E5:1 D5:0.5 r:0.5 | C5:2`、コード `Am7:4 F:2 G:2`。長さは拍、3連符は `1/3`
- 手引き(`worker/guide.js`、get_format_guide):書き方、決まり、良い曲にする作り方、米津玄師さんの曲によく見られる特徴(進行・メロディ・リズム・構成)を部品として記載。既存曲のメロディ・歌詞は使わない
- 失敗は「どの部品の何小節目の何拍目の、どの音が、どのコードに合わないか」を返し、AIが自分で直せるようにした

### 破綻防止の決まりを変えた(要件 F4 の変更)

- 前:キーから外れた音は置けない
- 今:**キーの音か、その時鳴っているコードの音**なら置ける。キーにもコードにも合わない音は置けない
- 理由:借用和音・セカンダリードミナント(例:Aマイナーでの E7、Gm7→C7)が米津風の要で、前の決まりでは一切使えなかった
- MIDI取り込みの曲は今までどおり断らず、注意書きにする

### サーバー

- Cloudflare D1 `ganesya-music`(`migrations/0001_songs.sql`)。1曲1行、revision が合う時だけ上書き
- 保存用API(`worker/api.js`):外部設計の表どおり。revision 不一致で 409、失敗は `{ code, message, hint }`
  - キーから外れた音は保存用APIでは断らない(操作の中で確かめている。MIDI取り込みの曲を保存できる必要があるため)。形が正しくないものは 422
- MCP(`worker/mcp.js`、`worker/tools.js`):Streamable HTTP(状態なし)。ツール9個は外部設計どおり。曲の削除は出さない
  - generate_alternatives は seed と index を返し、replace_section の alternative に渡すと採用できる(別案を保存しないため)
- **仮の本人確認**:Worker の秘密の値 ACCESS_KEY(合言葉)。保存用APIは `Authorization: Bearer`、MCP は URL に入れる(`/mcp/<合言葉>`)
  - 設計(パスキー+OAuth+Cloudflare Access)とは違う。E2・E4・E5 で置き換える。それまでは、合言葉を知っている人は誰でも曲を読み書きできる

### 画面

- 合言葉の入力(一度入れれば端末が覚える)→ 曲一覧(開く・削除・新しい曲)→ 編集
- 操作のたびに自動保存。右上に「保存済み/保存中…/未保存」
- 開いている曲が他(AI)で更新されたら、8秒以内に自動で読み込む。保存がぶつかった時は「最新を読み込む」を出す
- 曲一覧に「AIに曲を作ってもらう」手順と、コネクタに登録するURL(コピーボタン付き)

### 確かめたこと

- テスト95個(MCPの一連の流れ、手引きの作例がそのまま通ること、を含む)
- 手元(wrangler dev + ローカルD1)で、合言葉→一覧→開く→再生→自動保存→AIの変更の自動読み込み→衝突→新規作成 をブラウザで自動確認
- 本番で、合言葉なし・違う合言葉が 401 になること、MCP の initialize、create_song(「宵の残り火」を作成)を確認
- まだ確かめていない:Claude のアプリからコネクタとして実際につなぐこと(利用者の操作が必要)

### 手元で動かす

```sh
npm run dev:worker   # Worker(保存用API・MCP)を 8787 で。合言葉は .dev.vars の ACCESS_KEY
npm run dev          # 画面。/api と /mcp は 8787 に回る
```

## スプリント3.5(「MCPはOAuthじゃないの?」「音が安っぽい」を受けて)

### MCP を OAuth にした(E4)

- 前回の「URLに合言葉を入れる」方式は、設計(OAuth)と違う近道だったのでやめた。`/mcp/<合言葉>` はもう通らない
- `worker/oauth.js`:OAuth 2.1 の認可コード+PKCE(S256)、クライアントの自動登録、許可証の更新(使うたびに入れ替え)
  - 許可証は1時間、更新用は60日、認可コードは5分・1回限り。どれもハッシュで保存(`migrations/0002_oauth.sql`)
  - 許可の画面(`/oauth/authorize`):何を許すかを表示し、本人確認をして「許可する」
- コネクタに登録するURLは `https://ganesya-music.t4qjpmb66z.workers.dev/mcp`(秘密は入らない)
- **まだ仮の部分**:許可の画面と保存用APIの本人確認は合言葉。パスキーのログイン(E2)を作って置き換える。Cloudflare Access(E5)も未着手
- 確かめたこと:テスト(登録→許可→交換→更新、違う合言葉、PKCE違い、コードの再利用、未登録の相手、違う戻り先)。本番で 401 → 案内 → 登録 → 許可 → 許可証 → MCP の一連
- まだ確かめていない:Claude のアプリから実際にコネクタとしてつなぐこと

### 楽器を録音の音にした(C2 の差し替え、未決事項「音源の入手元」を決定)

- 音源:**FluidR3_GM**(MITライセンス。商用可・改変可・再配布可。`THIRD_PARTY.md` に表示)
- 録音の音にした楽器:ピアノ、アコースティックギター、エレキ(クリーン)、エレキ(歪み)、ベース、ストリングス、ベル(オルゴール)、ドラム
- 合成のままの楽器:シンセリード、シンセパッド、シンセ(厚い音)、サビ前の効果音。もともと電子音なので合成で作る
- 作り方(`scripts/build-samples.py`):fluidsynth で3半音おきに1音ずつ録音 → MP3(モノラル96kbps)→ 楽器ごとに1ファイル(.pack)。全部で5.3MB
- 鳴らし方(`src/audio/instruments/sampled.js`):一番近い録音を、再生の速さを変えて目的の高さにする。MP3の頭の無音は読み込み時に飛ばす(音の出だしのずれは10ミリ秒以内)
- 使う楽器の音源だけを、最初の再生の前に読み込む(1曲で2〜4MB)。読み込めない時は合成の音で鳴る
- 置き場:Cloudflare KV(`/sounds/v1/…`)。設計では R2 だが、このアカウントでは R2 が有効になっていないため。R2 を有効にしたら移す
- 音源を作り直す:`npm run sounds:build` → `npm run sounds:upload`(手元は `sounds:upload:local`)

## スプリント4(パスキーのログイン:E2、F12)

- 画面と保存用APIのログインをパスキーにした。合言葉でのログインは廃止(本番で 401 になることを確認)
- `worker/passkey.js`:署名の検証を外部ライブラリなしで実装(ES256・RS256)。確かめること:
  - 操作の種類、問いかけ(1回限り・5分)、出どころ(このサイトか)
  - このサイト向けのパスキーか、本人の操作があったか
  - 署名が登録した公開鍵のものか、利用回数が戻っていないか
- `worker/auth.js`:外部設計の `/api/auth/*`(register/start・finish、login/start・finish、logout、me)+パスキーの一覧・削除
  - ログイン中の印はクッキー(HttpOnly・Secure・SameSite=Lax、30日)。サーバーにはハッシュだけ保存
  - 書き換える操作は、このサイトの画面からのものだけ受ける(Origin を確認)
- パスキーの登録ができるのは次の2つ:
  1. ログイン中の人(合言葉なしで追加)
  2. **登録用の合言葉**を知っている人(初めての端末)。合言葉はここだけで使い、ログインには使えない
  - 設計では 2 は「Cloudflare Access の内側からだけ」。Access(E5)を入れたら合言葉を外す
- 複数登録できる(10個まで)。最後の1つは削除できない
- MCP の許可画面(OAuth):ログイン中なら「許可する」を押すだけ。ログインしていなければログイン画面へ行き、ログイン後に許可画面へ戻る。よそのページからの「許可する」は受けない
- 画面:ログイン画面(S0)、曲一覧の下にパスキーの一覧・追加・削除とログアウト(S8の一部)
- 登録ではブラウザが取り出した公開鍵を受け取る(機種の証明書は確かめない)。iPad の Safari 16 以降、Chrome・Edge の最新版が対象

### 確かめたこと

- テスト101個:登録→ログアウト→ログイン、別の鍵の署名・問いかけの使い回し・偽サイト向けの署名・別サイト用のパスキー・未登録・よそのページからの操作を通さないこと
- 手元で、仮想のパスキーを使ってブラウザで自動確認:登録 → 曲の作成と保存 → ログアウト(APIが401)→ パスキーでログイン → 再読み込みしてもログイン中 → 許可画面 →「許可する」→ 許可証 → MCP。ログアウト中に許可画面へ来た時の、ログイン → 許可画面への戻り
- 本番で:未ログインは 401、古い合言葉でのログインは 401、登録は合言葉が違うと 401、よそのページからは 403
- **まだ確かめていない**:実機(iPad・PC)でのパスキーの登録とログイン。本番に試しのパスキーを作ると入口が増えるので、こちらでは登録していない

## スプリント4.5(「シンセが強くて安っぽい」「商業に出せる音にしたい」を受けて)

### シンセの比率を下げた

- 叩き台の楽器の組み合わせを、録音の楽器中心に変えた(`src/core/composer/styles.js`)
  - 切ない:ピアノ / アコギ / ストリングス / ベル(変更なし、すべて録音)
  - 疾走感:歌メロをシンセ→ピアノ、背景をシンセパッド→ストリングス、彩りをエレキ(クリーン)に
  - ダーク:歌メロをエレクトリックピアノに、背景をストリングスに、彩りをベルに
  - 明るい:歌メロをエレクトリックピアノに
  - 和風EDM:リフをシンセ→**琴**に、背景をストリングスに。シンセは歌メロと和音の2つだけ
- 楽器を2つ追加(録音):エレクトリックピアノ、琴。全部で13種
- 残したシンセ(リード・パッド)は角を丸めた音に作り直した
- すでに作った曲の楽器は変わらない(画面の「楽器」で選び直せる)

### 録音を「弾く強さ」別にした

- ピアノ・エレピ・アコギ・ベース・琴は弱・強の2種類、ドラムは弱・中・強の3種類を録音(`scripts/build-samples.py`)
- 弱く弾いた音は音色そのものが柔らかい。弾く強さに近い録音を選ぶので、のっぺりしにくい
- 音源は全部で 9.6MB(1曲で使うのは 3〜6MB)。置き場の道を `/sounds/v2/` に上げた

### 仕上げ(ミックスとマスタリング)

- パートごとに低い音を削る(ベースとバスドラムの居場所を空ける)。響きの低い所も削る
- 残響を作り直した:元の音との間(18ミリ秒)、最初の跳ね返り、後ろほど高い音が消える減り方
- 全体:聞こえないほど低い音を切る、300Hz付近の濁りを少し下げる、高い所を少し上げる。全体のまとめ(コンプレッサー)はゆるめにした
- **WAVの書き出しを配信の基準にそろえる**(`src/audio/master.js`):-14 LUFS(主な配信サービスの基準)、最大 -1 dB
  - 大きさの測り方は ITU-R BS.1770(K特性の重み付け、ゲート付き)。基準の波形で値を確かめるテストあり
  - 雰囲気5種とAI作の曲で、-14.0〜-14.3 LUFS、音割れなしを確認

### 「商業に出せる音」について(現状の整理)

- 権利:音源は MIT ライセンスで、作った曲は商用に出せる
- 大きさ:配信の基準に合わせた
- 音の質:FluidR3_GM は2000年代の無料の汎用音源で、市販曲の水準には届かない。歌メロも楽器が代役をしている
- 次に効くこと(効果が大きい順)
  1. 歌声(P2、VOICEVOX)。歌が入ると印象が一番変わる
  2. 楽器ごとに上質な無料音源へ差し替え(ピアノ、ドラム、ベース、ギターの順)。ライセンスの確認が要る。差し替えは `scripts/build-samples.py` と同じ形の .pack を作れば済む
  3. パートごとの音声ファイル(ステム)の書き出し。DAW で仕上げたい時の出口(接続口設計の「将来」)

## スプリント4.6(「まだ安っぽい・機械的・奥行きがない。ピアノやドラムがちゃんとした音でないと」を受けて)

原因を3つに分けて直した。

### 1. 音源を入れ替えた

- FluidR3_GM → **MuseScore_General_HQ**(MIT。ピアノはパブリックドメインのグランドピアノ、ストリングスは CC0 の室内オーケストラ。`THIRD_PARTY.md`)
- ピアノは強さ3段階、ドラムは4段階。ピアノ・エレピ・ストリングス・ドラムは左右の広がりを残した録音(ステレオ)
- 音源は全部で15MB(ピアノだけで4.8MB)。1曲の初回の読み込みは8〜11MB。置き場の道は `/sounds/v3/`
  - 気になる点:モバイル回線だと初回の読み込みに時間がかかる。必要なら、ピアノの録音を間引くか圧縮を上げる

### 2. 演奏に表情を付けた(`src/core/performance.js`)

- 曲データは楽譜どおりのまま、鳴らす直前に揺れを付ける。同じ曲なら毎回同じ演奏(再生とWAVが一致)
- タイミング:楽器ごとに数ミリ秒の揺れ。スネアは少し後ろ、バスドラムは正確、ハイハットは細かく揺れる
- 和音のばらし:ギター・琴は弦を順に弾く(表拍は下ろし、裏拍は上げ)。ピアノは指がわずかにずれる
- 強弱:拍の頭は強く裏は弱く。Aメロは抑えめ(0.9倍)、サビは強く(1.06倍)、Bメロは後半に向けて盛り上げる
- ドラムは叩くたびに高さと大きさがほんの少し違う(3通りを使い回す)
- MIDIの書き出しは楽譜どおりのまま

### 3. 奥行きを付けた(`src/audio/render.js`)

- 全部の生楽器を同じ「部屋」(0.45秒の短い響き)に通し、ばらばらの音を1つの演奏にまとめる
- 長い響きの量で前後を描き分ける:歌・ドラムは手前、和音は中ほど、背景のストリングスは奥

### 確かめたこと

- テスト110個(同じ曲なら同じ演奏、ずれは最大70ミリ秒以内、サビはAメロより強い、ギターの和音が順に鳴る、を含む)
- 6曲を書き出し、-14 LUFS・音割れなし。再生の経路もブラウザで確認
- 聴いての確認はしていない(作業環境では音を聴けない)。数値と仕組みで確かめた範囲

## スプリント5(P2 歌詞と歌声:F8、F9)

### 技術調査の結果(要件「P2着手前に歌声合成の技術調査を行う」)

VOICEVOX ENGINE 0.26.2 を作業環境で実際に動かして確かめた(公式の Docker イメージ)。

- 歌わせる手順:`POST /sing_frame_audio_query?speaker=6000`(楽譜 → 歌い方)→ `POST /frame_synthesis?speaker=<歌い手>`(→ WAV)
- 楽譜は `{ notes: [{ key, frame_length, lyric }] }`。先頭は休み。1秒 = 93.75フレーム。返る音声は 24000Hz・モノラル
- 歌詞は1音符にかな1音。「きゃ」「ふぁ」「てぃ」「ヴ」「っ」「ん」は通る。「ー」と空白は断られる(「ー」は前の母音にして送る)
- 歌い手は81種類(30キャラクター)
- 速さ:19秒の部品を約5秒で作る(CPUのみ、4コア)。1コーラス(58秒)で約15秒
- ブラウザからの呼び出し(未決事項だった点)
  - 手元の画面(http://localhost)からは、そのままつながる
  - 本番の画面(https)からは、既定では断られる。VOICEVOX の設定(`http://localhost:50021/setting`)の「Allow Origin」に本番のアドレスを入れ、**VOICEVOX を再起動**するとつながる(Chromium で確認)
  - https の画面から http://localhost を呼ぶこと自体は、Chromium では止められない。新しい Chrome では「ローカルネットワークへのアクセス」の許可を聞かれることがある
  - iPad・スマホでは VOICEVOX が動かないので歌声は作れない(歌詞の編集はできる)。Safari は未確認

### 作ったもの

- 歌詞(`src/core/lyrics.js`):かなを1音ずつに分ける、メロディを息継ぎで区切る(フレーズ)、行ごとにフレーズへ割り当て、字余り・字足らずを行ごとに出す
- 操作「歌詞を入れる」(`setLyrics`):画面はズレを注意書きで知らせて入る分だけ入れる。MCP はズレがあれば断る
- MCP `set_lyrics`(10個目のツール):get_song がフレーズごとの音数を返し、AIはそれに合わせてかなの歌詞を書く。手引きに歌詞の書き方を追加
- 接続口 VOICEVOX(`src/connectors/voicevox.js`):楽譜への変換(頭からの位置で丸めてずれをためない、隣り合う音はつなげる)、使えるかの申告(使えない時は手順付きの理由)、歌い手の一覧
- 歌声の置き場(`src/audio/vocals.js`):中身(メロディ・歌詞・テンポ・歌い手)から作った鍵で覚え、再生とWAVで歌メロの楽器の代わりに鳴らす。メロディや歌詞を変えると古い歌声は使われない
- 画面:部品のパネルに「歌詞と歌声」。入力のたびに行ごとの音数の合い具合を表示、「歌詞を入れる」「歌わせる」、歌い手の選択(曲の `extensions.voicevox.singer` に保存)

### 確かめたこと

- テスト124個(かなの分け方、フレーズ、割り当て、楽譜の長さが部品の長さと一致、MCPでの歌詞)
- 本物の VOICEVOX で「宵の残り火」1コーラスを歌わせ、WAVに書き出した(歌い手3種)。歌の出だしは楽譜の位置と一致(子音の分だけ0.03〜0.08秒早い = 自然な歌い方)
- 画面から:歌詞を書く → 音数の表示 → 歌詞を入れる → 歌わせる → 再生、をブラウザで自動確認

### まだできていないこと

- 歌声はメモリ上だけ(ページを閉じると消える)。保存先(設計では R2)に置く
- 「全部歌わせる」のボタン、歌声の音量つまみ
- 漢字まじりの歌詞の表示(字幕用)。今はかなだけ
- AI が歌詞の別案を出す画面(F8 の 2〜3)。今は MCP 経由で Claude に書かせる
- VOICEVOX・キャラクターの利用規約の表示(画面内)

### 訂正(スプリント5の「確かめたこと」)

- 最初に渡した歌入りのサンプル3つには、歌が入っていなかった(利用者の指摘で判明)
  - 原因:サンプルを作る手元のスクリプトの問題。直前にファイルを書き換えたため、開発サーバーが歌声の置き場(`vocals.js`)を2つ読み込み、歌声を入れた側と書き出しが見る側が別になった。アプリ本体の不具合ではない
  - 「歌の出だしが楽譜の位置と一致」という確認は、歌声ではなく歌メロのピアノを測っていた可能性がある(区別できない測り方だった)
- 測り直した確認方法(歌が入っているかを区別できるもの)
  - 歌入りと歌なしの波形の相関:0.99(入っていない)→ 0.67(入っている)。歌い手を変えると 0.58〜0.60
  - 声の帯域(1〜4kHz)の割合:歌なし 4% → 歌入り 37%
  - ビルド済みの画面(本番と同じ中身)で、サビだけ歌わせて WAV を保存 → Aメロ 3%、Bメロ 7%、サビ 40%
  - 歌と伴奏の大きさ:歌 -18.4 LUFS、伴奏 -20.4 LUFS(歌が 2 LU 大きい)

## スプリント5.5(「ライラック」「ピースサイン」のようなロックを作りたい)

特定の曲のメロディ・コード・歌詞は使わず、J-ROCKによく出る型だけを部品にした。2曲の正確なコードは確認できていないので、「この曲はこう」という作りにはしていない。

### 雰囲気に「ロック」を追加(`rock`)

- 編成:歪んだギターのパワーコード、8分で刻むベース、8ビートのドラム、ピアノの歌メロ代役、弦の背景、クリーンギターの彩り。イントロは歪みギターのリフ
- ドラム:Aメロ・Bメロは `rock-verse`(8分のハイハット)、サビは `rock-open`(開いたハイハットで開放、バスドラム多め)
- 進行の型:王道進行・小室進行の変形、Aメロのベースが動く進行(1 → 5/7 → 6 → 1/3 → 4 …)、サビ前の ii–V–iii–vi と V7sus4 → V7 の溜め
- テンポ 140〜184、歌い手が歌いやすい主音
- MCP の手引きに「ロックの作り方」を追加(キー、構成、進行、メロディの運び、ドラム)

### 作例「夜明けのシャウト」(`examples/rock-yoake.mjs`)

- オリジナル曲。キー B minor、テンポ160、構成:イントロ → A → B → サビ → 2番(A・B・サビ)→ Cメロ → ラスサビ → アウトロ(108秒)
- コード:サビは G–A–D–F#7(Bm の外の音 A# を含む F#7 で引っぱる)、Bメロ最後は A7sus4 → A7 で溜める、Cメロは Bm–G–Em–F#7 から G–A–A7 でラスサビへ持ち上げる
- 歌詞(かな)も付き、全行の音数がメロディに合っている。歌詞の入れ方・歌い手は画面で変えられる
- 本番の曲一覧に登録済み(MCP から作成)。歌詞は、いまのコネクタには歌詞を入れる道具が出ていないため、画面で入力する(コネクタをつなぎ直すと `set_lyrics` が出る)

### ミックスの改善(歌が伴奏に埋もれる問題)

- 測ったところ、ロックの伴奏では歌が伴奏より約4 dB小さかった
- 歌の帯域(3kHz付近)を持ち上げ、ギター・背景・彩りのその帯域を下げた(`render.js`)
- 歌の音量を雰囲気ごとに変えた(`vocals.js`):ロック 1.5 / 疾走感 1.4 / 和風EDM 1.4 / ダーク 1.25 / ほか 1.15。歌メロのつまみで微調整できる
- 結果:歌と伴奏の大きさの差は 0〜+1 dB(部分ごとに測定)
- 測定用に、コンプレッサーを通さない書き出し(`renderSong(song, { dynamics: false })`)を追加

### 測定で気づいたこと(自分の失敗の記録)

- 開発サーバー(Vite)は、ファイルを書き換えると読み込み先に更新時刻付きのURLを作る。そのせいで歌声の置き場が2つになり、歌声が入らないまま測ってしまうことがある。ファイルを書き換えたら、サーバーを立て直してから測る
- 全体にかかるコンプレッサーは、歌だけ・伴奏だけで測ると本番の混ざり方とずれる。バランスは、コンプレッサーを通さない書き出しで測る

## 作業依頼書「音質改善と機能追加」(2026-11-17)に基づく作業

依頼書: https://claude.ai/artifact/WokTanWdRGhbTyhfnctHzW。3フェーズで進める。依頼書は「楽器を発振器で鳴らしている」前提で書かれていたが、実際はスプリント4.5〜4.6で録音の音源に替わっており、Q1〜Q4の大半はすでに入っていた。突き合わせて、残りの穴を埋めている。

### フェーズ1(音の土台)

| 項目 | 状態 |
| --- | --- |
| Q1 サンプリング音源 | 済み(MuseScore_General_HQ、MIT)。シンセ3種(リード・パッド・厚いシンセ)は、電子音そのものなので合成のまま |

### フェーズ2(盛り上がりの設計)

並びの1か所ごとの設定は、曲データの並びの項目に任意の項目を足して表す(`mix`・`styles`・`instruments`・`fx`)。部品のメロディとコードは共有のまま、時間軸を作る時(`src/core/item-parts.js` → `timeline.js`)に反映するので、再生・WAV・MIDIに同じ設定が効く。既存の曲は変えずに開ける(formatVersion は据え置き)。

| 項目 | 状態 |
| --- | --- |
| F2 部品ごとのミュートと音量 | 済み。`mix: { t4: { muted: true } }`(落ちサビでドラムを抜く)、`{ volume: 0〜1 }`。歌(t1)も消せる。MCP は update_arrangement の `set_item`、画面は部品パネルの「この場所だけの設定」 |

### F8 音声の書き出し(MCP の `export_audio`、`get_export`)— 依頼書で一番大切とされた項目

- **方式**:音は画面と同じ仕組み(ブラウザの Web Audio)で作る。Workers には Web Audio がないので、Cloudflare の **Browser Rendering**(サーバー側のヘッドレス Chrome)にアプリの書き出しページ(`/render`)を開かせて作る。**画面の書き出しと同じ音**になる(サーバー用に音の処理を作り直すと別の音になり、残響などの作り直しも大工事なので、採らなかった)
- 流れ:`export_audio` → Worker がブラウザを起動 → 曲データをページが開く前に渡す(`evaluateOnNewDocument`)→ ページが WAV を作り、8MBずつ `/render/part/…` に送り、終わったら `/render/done/…` に結果を書く → 一時保存(KV、1時間)→ `/download/<token>/<名前>.wav` で受け取る
- **待たせすぎない**:`export_audio` は最大25秒待つ。終われば URL を返す(`status: "done"`)。終わらなければブラウザはそのまま動かし続け(`keep_alive` 3分)、`status: "running"` と `jobId` を返す。あとから `get_export` に `jobId` を渡して受け取る。ページ自身が結果を書くので、Worker が待ち続ける必要はない
- 守り:token は HMAC 署名つき(秘密の値 `RENDER_SECRET`)で、その書き出し1回だけに使える。アップロードは署名が合うものだけ、1回8MB・40個まで。ダウンロードのURLは「知っている人は誰でも受け取れる」ので1時間で切れる(手引きにも書いた)
- 確かめたこと(本番):「夜明けのシャウト」(110.6秒)を書き出し、19.5MB・音割れなし・画面の書き出しと同じ仕上がり。25秒で「処理中」→ 状態を引くと完了 → ダウンロードできた。署名のないアップロードは403、でたらめなURLは404。テスト142個(署名、分割の保存とつなぎ、でたらめの拒否、状態の遷移、道具の返事)
- **時間**:全体で22〜43秒。内訳はブラウザの起動 約0.7秒、音づくり 10〜21秒、送信 2.5〜4秒。サーバー側のブラウザの混み具合でばらつく。曲が長いほど延びる(3分の曲なら1分を超えることがある)。`itemIds` で一部だけ書き出せる
- **制限**(Browser Rendering):短い時間にブラウザを何度も起動すると 429(起動回数の上限)になる。道具は「1分ほど待って」という失敗を返す。このアカウントの上限は、今回の試験では5回前後/数分で当たった
- **歌声は入らない**:歌声(VOICEVOX)は利用者のPCで作り、サーバーには保存していないため。楽器の演奏だけが書き出される。歌入りの音声は、画面の「音声ファイル(WAV)で保存」(歌わせたあと)を使う。歌声をサーバーに保存すれば、MCPの書き出しにも入れられる(次の課題)
- 画面の書き出しは今のまま使える(同じ処理)

### F4 歌メロの複数化、F6 キー外の音の印、F7 フレーズ区切りの記法

| F4 歌のパートを足す | `addVocalPart`(MCP `add_vocal_part`、画面の「＋ ハモリ(上)/(下)」)。harmony を渡すと主旋律からキーの中の音でハモリを作り(3度でコードに合わない音は隣のコードの音に寄せる)、歌詞も写す。省けば空のパート(デュエット・掛け合い用。replace_section の parts で書く)。4本まで。`removeVocalPart` で外せる(主旋律は不可)。歌詞はパートごと(`setLyrics` の `trackId`、MCP set_lyrics の `trackId`)。歌い手もパートごと(`extensions.voicevox.singers`、初期は主旋律がずんだもん、ほかは四国めたん)。「🎤 2人で歌わせる」で全パートを VOICEVOX に歌わせ、重ねて鳴らす。get_song に `otherVocals` が出る |
